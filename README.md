# 星坠之谜 · 文字卡牌RPG

一款零依赖的网页文字/卡牌 RPG。黑暗奇幻背景：星坠之夜，你受命调查雾隐镇北的迷雾矿坑，
在分支剧情与属性检定中推进冒险，用卡牌战斗击败矿坑之王与堕落守塔人。

## 如何运行

**双击 `index.html` 即可游玩**（Chrome / Edge），无需安装任何东西。

进度会自动保存在浏览器本地（localStorage），标题画面可"继续冒险"。

## 玩法

- **剧情推进**：阅读故事、选择分支。`🎲 属性检定` 掷 d20 + 属性×2，达到 DC 即成功；
  力量 / 敏捷 / 智力 / 魅力各有用武之地——点击左侧面板的属性可查看用途说明。
- **卡牌战斗**（类《杀戮尖塔》）：每回合 3 点行动力、抽 5 张牌；敌人头顶会展示意图
  （⚔️攻击 / 🛡️防御 / ⬆️强化 / ☠️诅咒）。状态：中毒 / 虚弱 / 易伤 / 力量。
- **成长**：战斗胜利获得金币、经验，并三选一拿新卡；商店购装备与药水；战后战利品随机。
- **冒险笔记**：📓 自动记录任务进度（主线/支线）与听来的情报线索（酒馆传闻、矿监日志、
  托马斯的警告等）。角色面板下方"翻开笔记"或菜单中可随时查阅——谜底往往藏在笔记里。
- **星陨林（支线区域）**：第二章岔路口踏入猎人小径——药婆雾葵的净化泉眼支线、雾角鹿
  遭遇、精英战「林心低语者」，以及与低语做交易的契约分支。你的选择会写进结局尾声。
- **三个结局**：星光 / 新王 / 长夜。星核的抉择决定结局——净化（星光，检定失败也仍会净化，
  只是要以血肉为代价）、吸收（新王）、封存（长夜，直接带碎片回镇，不必登上塔顶）。
  支线（救援矿工、酒馆情报、星陨林）会写进尾声的前几段。
- **存档自愈**：读档时会自动清理已失效的卡牌 / 装备 / 物品 / 场景引用并补齐缺失字段，
  被修复的内容会写进日志并弹出提示，不会因为版本更新而卡在白屏。
- **快捷键**：战斗中 `1~9` 出牌，`E` 结束回合；点击剧情文字可跳过打字机动画。
- **移动端**：窄屏下顶栏出现 🎒 按钮，可滑出角色面板使用物品、查看牌组与笔记。

## 项目结构

```
index.html        页面骨架
css/style.css     暗黑奇幻主题样式
js/data.js        全部游戏数据：39 张卡牌、16 种敌人、装备/物品/商店、39 个剧情场景
js/state.js       存档（含旧存档自愈）、角色、任务/笔记（journal）、效果结算、升级
js/ui.js          角色面板、打字机、弹窗（笔记/属性说明）、浮动数字、WebAudio 合成音效
js/story.js       剧情引擎：场景跳转、属性检定、分支
js/combat.js      卡牌战斗引擎：回合流程、意图 AI、状态、奖励
js/main.js        标题画面、菜单、读档、死亡画面、快捷键
tools/validate.js 数据一致性校验（node tools/validate.js）
tools/save_test.js 存档自愈 + 战斗回合边界回归（node tools/save_test.js）
tools/*_test.py   Playwright 浏览器测试（冒烟 / 深度通关）
```

## 开发与测试

```bash
node tools/validate.js      # 数据一致性校验（ID 引用 / 语法 / 逻辑冒烟）
node tools/save_test.js     # 存档自愈 + 战斗边界回归（67 项断言，无需浏览器）
 python tools/smoke_test.py  # Playwright 浏览器冒烟测试（需 msedge）
 python tools/deep_test.py   # 全场景遍历 + 两结局通关 + 星陨林支线 + 死亡复活
```

`tools/validate.js` 检查 ID 引用，`tools/save_test.js` 检查读档健壮性与回合边界
（重洗牌、状态递减、护甲清零、放弃战斗后的异步安全）——两者都是纯 Node，无依赖。

扩展新内容只需编辑 `js/data.js`：加卡牌往 `DATA.CARDS` 加条目、加敌人往 `DATA.ENEMIES`
并挂进 `DATA.GROUPS`、加剧情往 `DATA.SCENES` 写场景（支持函数文本、检定、战斗触发、
onEnter 钩子）。新增任务/笔记：先在 `DATA.QUESTS` / `DATA.NOTES` 定义，再在场景钩子里
调 `Quest.add(state,'id')` / `Note.add(state,'id')`，或直接写在选项效果上
`fx: { quest: 'id', note: 'id' }`。跑一遍 `tools/validate.js` 即可确认引用无误。
